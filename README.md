## Задача 1: Обеспечить разработку.  
Для организации процесса разработки я предлагаю использовать `GitLab.com (SaaS)` в сочетании с `GitLab Self-Hosted Runners.` 
Это единая облачная платформа, которая полностью закрывает все предъявленные требования.

### Соответствие требованиям

| Требование                                           | Реализация в GitLab                                              |
|------------------------------------------------------|------------------------------------------------------------------|
| Облачная система                                     | GitLab.com (SaaS)                                                |
| Система контроля версий                              | Git (встроенный)                                                 |
| Репозиторий на каждый сервис                         | Отдельный проект на каждый микросервис                           |
| Запуск сборки по событию из Git                      | Webhooks + Pipeline triggers (push, MR, tags)                   |
| Запуск сборки вручную с параметрами                  | Manual triggers + Pipeline variables                             |
| Привязка настроек к каждой сборке                    | CI/CD Variables (Project / Group / Instance level)               |
| Шаблоны конфигураций                                 | Include + Template repository (`.gitlab-ci.yml` шаблоны)         |
| Безопасное хранение секретов                         | Masked + Protected Variables, Secret Manager                     |
| Несколько конфигураций из одного репозитория         | Multiple jobs / pipelines + rules / workflow: rules              |
| Кастомные шаги                                       | Arbitrary shell / script steps                                   |
| Собственные Docker-образы                            | `image:` в `.gitlab-ci.yml`                                      |
| Агенты сборки на собственных серверах                | Self-hosted GitLab Runners (Docker / Kubernetes executor)        |
| Параллельный запуск сборок                           | Поддерживается нативно                                           |
| Параллельный запуск тестов                           | `parallel:` + `needs:` / DAG pipelines                           |

`GitLab` лучше всего соответствует требованиям крупной компании, так как сочетает в себе систему контроля версий и мощный CI/CD в одном продукте.  

Альтернативы, которые я рассматривал:  

`GitHub Actions` — хорош, но уступает в удобстве управления self-hosted runners и встроенных шаблонах на уровне компании.  
`Jenkins` — очень гибкий, но требует значительно больше усилий на поддержку и безопасность.  

Вывод: `GitLab SaaS + Self-Hosted Runners` — это оптимальное сочетание облачной управляемости, удобства для разработчиков и полного контроля над выполнением сборок. Решение позволяет быстро масштабироваться и соответствует всем требованиям задачи.  

## Задача 2: Логи  

Для сбора, хранения и анализа логов предлагаю использовать EFK-стек в следующем составе:  

`Fluent Bit` — агент сбора логов
`Elasticsearch` — центральное хранилище и поисковый движок
`Kibana` — интерфейс для поиска и визуализации

Я выбрал `EFK (Fluent Bit + Elasticsearch + Kibana)` по следующим причинам:

```
Полностью соответствует всем требованиям задания.  
Fluent Bit очень лёгкий и производительный по сравнению с Fluentd и Logstash.
Elasticsearch + Kibana — зрелые и мощные инструменты для поиска и анализа.
Хорошо масштабируется в микросервисной архитектуре и Kubernetes.
Позволяет давать разработчикам доступ только на чтение без риска для инфраструктуры.
```

Альтернативы, которые я рассматривал:  

`Loki + Grafana` — легче и дешевле, но уступает в сложных полнотекстовых поисках.  
`Graylog` — удобный интерфейс, но тяжелее в эксплуатации.  

 Комбинация `Fluent Bit + Elasticsearch + Kibana` — надёжное, проверенное и функциональное решение, которое отлично подходит для крупной микросервисной системы.  

 ## Задача 3: Мониторинг

Для сбора и анализа метрик предлагаю использовать `Prometheus + Grafana`.

`Prometheus` — основная система сбора и хранения метрик.  
`Grafana` — инструмент для визуализации и построения дашбордов.  


Я выбрал `Prometheus + Grafana`, потому что:
```
Это de-facto стандарт мониторинга в микросервисных и Kubernetes-окружениях.
Отлично справляется со всеми перечисленными требованиями.
Поддерживает высокую детализацию метрик (до каждого пода/контейнера).
PromQL позволяет гибко агрегировать данные.
Grafana предлагает мощный и удобный интерфейс для создания дашбордов, который легко могут использовать разработчики.
Решение open-source, хорошо масштабируется и относительно просто в эксплуатации.
```
Альтернативы, которые рассматривал:  

`Zabbix` — сильнее в мониторинге хостов, но слабее в динамических микросервисных окружениях.  
`InfluxDB + Telegraf` — хорошая комбинация, но Prometheus лучше интегрируется с Kubernetes.  

Связка `Prometheus + Grafana` — наиболее подходящее, современное и проверенное решение для крупной микросервисной архитектуры. Оно обеспечивает полный сбор метрик и удобный интерфейс для команды.
